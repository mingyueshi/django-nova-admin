# NOVA Admin 功能扩展规划

- 日期：2026-10-24
- 适用对象：交互预览 1.8.0 / 原生 Django 主题 0.6.1
- 性质：经统筹复核后的分期规划；用户已授权合理范围由当前会话主导、指定实施会话执行。每项派发前固化范围与验收标准，通过独立验收后再推进；未派发项仍是候选，不视为全部承诺。
- 严重度/优先级：A 优先做 · B 次之 · C 可选 · D 长期

---

## 0. 设计原则（边界约束）

所有扩展必须遵守主题的一贯定位，否则宁可不做：

1. **呈现层优先**：只做皮肤、交互组件与渲染框架，不新增权限、认证、业务逻辑或数据库模型。
2. **数据由宿主注入**：统计/计数/列表数据由宿主按用户、租户、对象及字段权限过滤后注入；`get_queryset` 是接入点之一，不自动等于完整授权。主题只负责渲染。
3. **示例 ≠ 默认行为**：导入导出、私有媒体、审计等做成"可复制示例"，不悄悄改变未知项目的默认行为。
4. **空态明确**：无数据时必须显示明确空态，不得复用预览的合成 KPI 冒充真实数据。
5. **原生可回退**：切回原生/关闭主题时，增强功能不留下残留或破坏原生流程。

## 1. 呈现层组件化（优先级 A）

主题已经具备权限过滤导航、分组/收藏、移动端导航、排序提示、列表横向滚动及筛选折叠等交互。以下是增量扩展；涉及持久化、对象操作或任务状态的部分必须与纯呈现拆开验收，不能整体归为低风险。

### 1.1 命令面板（Command Palette）

- **目标**：在已有 ⌘K 搜索提示的基础上，做成全局命令面板。
- **要点**：搜索模型与应用、最近动作、外观/密度/配色切换、跳转页面；数据只消费权限过滤后的菜单，键盘可操作、Escape 关闭、焦点返回。
- **可复用**：`dist/js/presentation.js` 的快捷键展示约定；真实主题从当次服务端权限过滤后的导航 DOM 取数据。预览菜单与真实主题的数据源不同，不直接搬用 mock 菜单。
- **边界**：纯前端，不新增后端端点。

### 1.2 通知 / 消息中心

- **目标**：把 Django 的 `message_user` 整理为当前响应内可统一查看、折叠和关闭的消息区域；跨页归档另行设计。
- **要点**：首版仅对当前响应中的消息按级别组织、折叠/关闭，保留原生 messages 与无 JS 回退。
- **边界**：跨页归档/已读需要独立的保留期限、账号隔离与敏感信息契约，不把消息内容直接存入持久化浏览器存储。

### 1.3 统一偏好面板

- **目标**：把散落的密度、配色、明暗、每页条数收进一个"设置"入口。
- **要点**：复用已有偏好提交与 CSRF 机制，不承诺跨登录态联动。真实主题明暗/配色使用 session；预览使用浏览器状态。密度当前有宿主 CSS 预设，每页条数属于受限 ModelAdmin 分页契约，不能只新增一个前端开关。
- **可复用**：`palette.js`、`preferences.py`、`PALETTE_PRESETS_ZH.md`。

### 1.4 列表增强套件

- **目标**：提升长列表的操作效率。
- **要点**：列宽拖拽、固定首列、行内 change/delete 链接、批量操作的进度反馈。
- **边界**：删除继续用原生确认 + CSRF POST；行内链接逐对象走权限 hook。
- **拆分**：列宽与固定列可单独做呈现增强；行操作做宿主示例；批量任务进度必须由真实任务状态驱动，无任务协议时不展示模拟百分比。

### 1.5 表单增强

- **目标**：改善复杂表单的可读性。
- **要点**：字段 tab 分组、fieldset 折叠记忆、inline 拖拽排序、只读字段"一键复制"。
- **边界**：不替换原生 ModelForm 与校验，只做呈现与局部交互。
- **拆分**：tab/折叠/复制与排序分别验收；inline 持久化排序依赖排序字段、formset 和宿主保存契约，无该契约时不提供看似已保存的拖拽排序。复制需处理权限、敏感字段与失败反馈。

### 1.6 打印 / 只读导出视图

- **目标**：面向政企内网的纸质归档场景。
- **要点**：`@media print` 样式 + "打印当前列表"按钮。
- **边界**：打印只读，不引入下载/导出权限。

## 2. 前端预览能力"回灌"真实主题（优先级 B）

`dist/` 已有图表与分析交互预览；真实主题尚无对应通用图表框架，但已有首页模板接入指南和导航数据钩子。预览可复用的部分仍需真实数据、权限、生命周期和资源预算验收，不能直接视为生产成熟组件。

### 2.1 图表卡片组件 + 数据钩子

- **目标**：提供 ECharts/Chart.js 的卡片模板，宿主注入权限过滤后的聚合结果。
- **要点**：先定义版本化快照、空值/错误、时间范围/时区、数量限制和权限契约，再选一种图表实现；默认不带业务统计 API，也不同时捆绑多个大型图表库。
- **可复用**：`dist/js/analytics-*`、`chart-lab-*`、`ANALYSIS_LAB.md` 里已论证的"数据口径与接入用法"。
- **边界**：主题只出渲染框架，绝不自带统计 API；卡片的字段/范围由宿主校验。
- CSV 导出独立验收，明确允许列、导出授权、公式注入防护及数量限制；不能把“能看到聚合图”视为“可导出明细”。

### 2.2 联动下钻交互框架

- **目标**：把 `analysis-lab` 的联动/下钻/时间滑块抽象为可复用前端组件。
- **要点**：排行联动、下钻、时间范围和最后成功快照依次推进；下钻有键盘/触屏入口，权限或账号/租户变化立即丢弃旧快照，错误与过期状态明确显示。
- **可复用**：`analysis-lab.js`、`analysis-lab-options.js` 的生命周期与 AbortController 模式。

### 2.3 首页仪表盘区块

- **目标**：在 `AdminSite.index_template` 上做可选 KPI 卡片区。
- **要点**：空态明确、权限过滤、不替代原生应用入口。
- **边界**：不复用 mock KPI；无数据时明确空态。

## 3. 宿主集成示例（优先级 C）

这些此前反复出现在 `INTEGRATION_GUIDE.md`，但一直是文字指南，缺可复制 Demo。价值在于降低宿主接入门槛。

### 3.1 导入 / 导出

- CSV 导出（公式注入防护、列白名单、数据量限制）；导入四步（上传→解析校验→预览差异→确认提交，含事务与逐行失败策略）。

### 3.2 私有媒体

- `ImageField` + 授权下载/预览 + 内容净化（不可信 SVG/HTML 隔离）；现有 `media.py` 仅是合成图集，需明确区分。

### 3.3 密码重置流程

- 登录页已留 `admin_password_reset` 入口，补含邮件后端 + 防枚举响应的 Demo。

### 3.4 审计日志查看器

- `LogEntry` 的只读界面 + 按用户/动作/时间筛选；不新增日志采集。

### 3.5 MFA / 会话管理

- Axes（锁定）已接；MFA 作为安全 extra 的下一环，会话时长/`记住我` 策略由宿主决定。

## 4. 生态与工程化（优先级 D）

### 4.1 无障碍（a11y）持续验收（所有阶段）

- 已有对比度、键盘、焦点、ARIA 和浏览器响应式检查，不能写成“只做对比度”。每个新交互必须具备键盘、焦点返回、语义与无 JS 回退证据；物理设备和 NVDA/VoiceOver 实测单独记录，自动化通过不等于合规认证。

### 4.2 RTL / 深色全覆盖

- RTL 已有部分支持；做全组件覆盖验收 + 深色模式下的语义色核对。

### 4.3 i18n 扩展

- 沿用现有 PO/MO、编译及覆盖回归流程；新增语言还须检查复数、格式、长文案、键盘说明与 RTL，不能只补 PO 文件即宣称支持。

### 4.4 独立组件包

- 320 图标 + 图表组件拆成独立 `nova-ui` 包，供非 Nova 主题项目复用。

## 5. 优先级矩阵

| 优先级 | 方向 | 理由 |
|---|---|---|
| **A** | 导航命令面板 / 当前页打印 / 当前响应消息呈现 / 偏好入口整合 | 范围收窄后可逐项验证；a11y、i18n、深色与回退是每项门槛 |
| **B 前置** | 列宽/固定列、表单折叠/复制、行操作与排序契约 | 呈现与宿主操作分开；持久化/任务进度不归为纯前端 |
| **B** | 图表卡片 / 联动下钻框架 / 首页仪表盘 | 存量能力变现，严守"渲染框架 vs 数据钩子"边界 |
| **C** | 导入导出 / 私有媒体 / 密码重置 / 审计 / MFA | 降低宿主门槛，属示例、非默认 |
| **贯穿 / D** | a11y / RTL / i18n 贯穿各项；独立包暂缓 | 独立包待复用需求、API 稳定与维护成本证据成熟后再立项 |

## 6. 落地建议

1. 首项做 1.1 的导航命令面板，收窄到当前用户可见菜单；通过后再按实际反馈派发当前页打印等独立项目。
2. B 类是最大价值点，但必须先固化"数据钩子契约"，避免把预览的 mock 数据误当真实统计。
3. C 类每一项都要标注"示例、非默认"，且各自需要独立验收（尤其安全相关）。
4. 每项实施前，建议先在 `FEATURE_ROADMAP.md` 对应小节补充"确认范围 + 验收标准"，再进入实现。

## 8. PR1 当前列表打印

- 状态：2026-10-24 已完成本地独立验收；CSS加载失败的入口回退问题修复并复验通过，详细证据见`FEATURE_PROGRESS.md`。

- 打印明确标注“当前页显示内容”，不能把当前页写成全部结果。宿主仍负责对象/字段可见权限，支持明确的打印排除标记；隐藏行列、hidden/password/file控件及隐藏值不得因打印恢复显示。

- native/全局禁用/匿名/popup/非列表不增加入口；无JS或print不可用时保留原生页面与浏览器打印能力，不出现失效按钮。
- 验收包括三版Django权限/多站点/分页定向测试，真实Chromium中英文/明暗/手机屏幕和print media检查，以及本地打印PDF的内容/布局、长表/空表/编辑表格、取消/恢复/重复触发、0额外业务请求；打印对话框和物理打印机验收单独声明。
- 维持CP1、CSRF、原生排序/筛选/分页与编辑保存路径；现有导出器和资源预算按实际增量更新。未经本轮新增指令不提交、推送、发布或部署。
