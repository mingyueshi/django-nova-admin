## 单独的既有缺陷修复

`dfcdade` 为第四个、独立于三步重构的修复：商品批量动作中“发布所选”的 HTML option 起始标签原来误写为结束标签。旧站真实 Chrome 与基线测试均确认它不可选。本轮纠正该标签，恢复原有动作，并新增 7 项针对性检查；该套件在旧基线上按预期失败，在修复版通过，包括跨页确认范围、确认前不写入、仅修改选中项及清除选择。差异在 `review/bulk-publish-fix.patch`。

这是明确的旧 bug 修复，不计入第一步的“无行为差异”结论。工厂的 68 项边界检查仍同时通过旧基线与重构版。

## 必须保留的行为差异

| 行为 | 用户 | 商品 | 新闻 |
|---|---|---|---|
| 每页条数 | 6 | 5 | 5 |
| 文本搜索 | 不区分大小写 | 不区分大小写 | 区分大小写 |
| 排序按钮 | 日期排序，保留页码 | 保留原记录次序 | 日期排序，回第 1 页 |
| 清空筛选 | 清空选择、回第 1 页，保留排序 | 同左 | 同左 |
| 切页/排序 | 保留跨页选择 | 切页保留选择 | 保留跨页选择 |

直接在搜索框输入的长度行为保持原状；工厂不会把路由的 100 字解析限制悄悄套到键入过程。移动与桌面全选只作用于当前页，其他页已选记录保留。

## 接口约定

`createCollection` 是静态演示的本地列表状态工厂，不提供后端请求、权限、DOM 或保存能力。`getRecords()` 返回当前记录；`matches(record, state)`、可选 `compare(a, b, state)` 保留资源规则；各筛选项的 `parse` 只负责路由参数。`queryString()` 返回参数串，由页面交给主应用更新地址。

`saveRecords(records)` **同步返回 boolean**。主应用捕获本地存储异常，先保存成功才让资源模块替换内存记录；失败保留选中项、确认框和输入供重试。这里不是通用异步 API 契约。未来接入真实服务时，需要单独设计 `await`、取消/版本检查和服务端失败处理，不能直接把此函数换成返回 Promise 的请求。

商品列表开关仍在延迟结束后基于**当时最新的记录**更新，使用重置代次取消过期写入；编辑表单里明确修改过的选择优先。未把这些竞态保护简化成“仅禁用按钮”。
