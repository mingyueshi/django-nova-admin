## 报告需要纠正或限定的地方

1. 原生三版 Django 都使用 **#nav-filter**，Nova 旧版并没有把它改成别的 ID；关键词持久化实际是 **sessionStorage**，不是 localStorage。旧 Nova 脚本与原生筛选器同时工作才导致组/应用匹配不足；不能把 ID 归因当作既定事实。新脚本仅接管 Nova 自己的搜索输入，原生侧栏总开关仍由 Django 管理。
2. “opt-in”是安装与配置层的显式接入，不代表 `NOVA_ADMIN_ENABLED` 默认 False。保留现有 True 默认并把说明写清，避免补丁升级突然关闭主题。
3. Django app namespace 可以复用；重复实例 namespace 会得到系统检查警告并使反解存在歧义，不能一概描述成必然启动报错。文档要求不同实例明确命名并检查映射。
4. 没有某功能通常是可选产品范围，而不是皮肤层的安全缺陷：找回密码、锁定、MFA、上传、导入导出、仪表盘、通知、独立审计都需要业务/身份/权限设计。
5. 6.1 的英文空选项与中文生硬措辞确实可见；但是在主题里覆盖 Django 全局词典会影响原生恢复与其他页面。本轮不采用这种隐性覆盖，给出宿主级本地化接入方案。

## 明确后续选择，不在补丁中偷加

- 仪表盘：推荐在原生首页公开钩子上做可选业务模块，保持权限过滤；Mock 指标不搬进真实首页
- 行操作/跳页/每页数量：推荐宿主 ModelAdmin 的可选范式，删除保持原生确认和 POST；不先替换整张列表模板
- 即时外观切换/跟随系统：可以作为后续渐进增强，仍保留会话级保存和无 JS 表单，不改变已约定默认模式
- 上传控件/富文本：先确定真实文件存储、授权与输出净化，再加表现层；当前图集不是私有媒体参考实现
- 账户安全：沿用宿主认证体系。本轮没有新增密码重置、邮件、验证码、锁定或登录 API
- 主色、图标、标点、空状态插画：属于视觉/文案选择，提供可覆盖变量，暂不为偏好复制 Django 整页模板
- favicon、打印、缺货提示、新闻日期规则、date_hierarchy：可选增强，需结合业务；首批优先通用缺陷与回归保护
