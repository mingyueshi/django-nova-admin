# 配色预设使用与验收

可选医疗青、专业靛、文教紫、零售陶、石墨黑、午夜蓝、松林绿、暖琥珀。名称仅用于演示定位，不是行业标准；可以按实际品牌自由选用。

## 静态预览

在“系统设置 → 主题与恢复 → 配色方案”选择预设。登录预览的顶部也有相同选择。配色与浅色、深色、跟随系统互相独立；跨页、刷新和同源窗口可同步。选择“默认配色”恢复原来的企业蓝。

石墨黑使用中性灰黑底色，午夜蓝使用深靛蓝底色与淡蓝紫强调色，面板层次比默认深色更明显。松林绿使用森林绿底色与薄荷绿强调色，暖琥珀使用暖棕底色与琥珀强调色。选择配色后，将外观设为“深色”；选择“跟随系统”时会在系统深色模式下自动启用。这四套方案覆盖页面背景、侧栏、卡片、表单和登录页；浅色模式使用各自对应的强调色，不会因选择配色而强制改变外观。

偏好仅存于本地 `nova-palette`。存储被禁用或容量不足时仍可在当前页面切换，并提示偏好未保存；不会清除 `nova-theme` 或业务数据。

“原生恢复对照”保留原来的56个样本和目录页，包含48个配色代表页：八种配色 × 浅/深色 × 工作台/商品列表/登录页，共105页。代表页只展示标准密度，不能代表全部页面、auto和紧凑组合都已视觉验收。切回默认配色会恢复之前选择的页面、外观和密度。

## Django 接入

现有主题接入不变，可选设置：

```python
NOVA_ADMIN_DEFAULT_PALETTE = "default"
# 可选：default、teal、indigo、violet、terracotta、graphite、midnight、forest、amber
```

已保存的有效 session 偏好优先于默认设置。用户工具区中有独立的外观与配色选项，仍通过带 CSRF 的 POST 提交。旧客户端只传 mode 仍兼容，不会清除已选配色；非法组合不产生部分写入。

默认不变：通用主题仍保留原来的紫色主色和绿色保存按钮；演示项目仍是企业蓝。原生模式及关闭主题不加载 Nova 资源。危险、错误、成功、警告仍保留各自语义，图标复用 currentColor。

加载顺序：theme.css → tokens.css → presets.css → 宿主自定义 CSS。普通宿主 body.nova-admin 品牌变量覆盖仍可最后生效。选中/行背景的按模式覆盖方式见 [英文详细契约](PALETTE_PRESETS.md)。不需要 CSS 构建器。

石墨黑、午夜蓝、松林绿和暖琥珀增加 `--nova-surface-dark-*` 背景、文字及边框变量，只在深色或系统深色下映射；宿主仍可在后加载的同模式规则中覆盖。原生模式和全局关闭继续不加载配色样式。
